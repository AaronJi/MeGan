## ⚡ Quick Start: an exampled experiment on CrossFit&UnifiedQA (settings: non-nli-to-nli)

### training and eval
For ease of quick implementation, /data/metaicl/non_nli_to_nli has a small examples of the training set of non-nli-to-nli.

We currently have a subset (non-nli-to-nli) of CrossFit&UnifedQA uploaded to huggingface: https://huggingface.co/datasets/jiluoaaron/CrossFit-and-UnifiedQA, which can help develop the pipelines below.

```bash
bash eval_MetaICL_non-nli-to-nli.sh
```

## 🧠 Summary

This project is implemented on the basis of LlamaFactory 0.8.3. Questions to the basic usage can refer to the original repo: https://github.com/hiyouga/LlamaFactory/tree/v0.8.2.

---
## ⚙️ Data Processing

### Raw Data Preprocessing
All the data are converted to the messages format (in .jsonl). The `condition` has a key called `style` in the raw dataset due to the histrical reason. More data uploading is incoming.

Task descriptions of CrossFit&UnifedQA are automatically generated by GPT-4o. The full version of generated descriptions are in data/task_descs.yaml.

### Parsing and Aligning

We adhere to the `sharegpt` data format in LlamaFactory, with a new type of `style_tag` added to `DatasetAttr` in the [parser.py](src/llamafactory/data/parser.py). There might also be attributes of `history` or `context` in `DatasetAttr` depending on the detailed condition or dataset type. The sample is then processed by the `convert_sharegpt` function in [aligner.py](src/llamafactory/data/aligner.py). 

During training, the condition content is first converted into a natural expression by `get_style_expression` in [supervised.py](src/llamafactory/data/processors/supervised.py), then `preprocess_supervised_dataset` finally generates the supervision.

## 🚀 Model Configuration

We keep a local copy of the official llama model code with the implementation of beta-SwiGLU and the hypernetwork in [meta_swiglu_shared_modeling_llama.py](src/llamafactory/model/model_utils/meta_swiglu_shared_modeling_llama.py). We also implement another version of model code which has layer-wise hypernetworks in [meta_swiglu_modeling_llama.py](src/llamafactory/model/model_utils/meta_swiglu_modeling_llama.py).

### model loading:
One of the above model objects (`LlamaForCausalLM_sharedHyper` or `LlamaForCausalLM`) is loaded by [loader.py](src/llamafactory/model/loader.py), depending on the configuration of `meta_swishglu_shared_hyper`. 

### hyperparameter passing:
To automatically customize the model architecture by script configurations, one need to execute the setattr method within the patch_config function in [patcher.py](src/llamafactory/model/patcher.py), to pass the running config (e.g., meta_swishglu_attn_key) to model_args.

### revised objects:
We create a new model object called `LlamaForCausalLM_sharedHyper` in [meta_swiglu_shared_modeling_llama.py](src/llamafactory/model/model_utils/meta_swiglu_shared_modeling_llama.py), which has the following hierarchy:
- LlamaForCausalLM_sharedHyper
- LlamaModel
- LlamaDecoderLayer
- LlamaMLP
- HyperStyle2Beta

in which `HyperStyle2Beta` is the **hypernetwork** which is fed into the text expression of condition and the layer index, and outputs the layer-specific beta.
